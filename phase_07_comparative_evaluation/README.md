## Run

On the GPU server, from the checkout root, using the working Phase 3 CUDA environment:

```sh
setsid nohup bash phase_07_comparative_evaluation/hpc/run_phase7.sh \
  > outputs/phase_07_comparative_evaluation/phase7-driver.log 2>&1 < /dev/null &
```

The script runs these steps in order:
1. Environment and dataset checks.
2. The test suite.
3. Checkpoint verification.
4. Smoke runs: one fixed question per language for each model, then a check that every model covers the same four IDs.
5. Full inference with `shared.evaluate` scoring. Each model must score 2,351 rows with the frozen file's per-language counts.
6. Paired statistics, the error sample and the translated reuse.
7. The report and plots, plus a run archive.

Environment variables override the defaults: `PHASE7_PYTHON`, `PHASE7_STEP1`, `PHASE7_RUN` and `PHASE7_BATCH_SIZE`. To resume a run, rerun with the same `PHASE7_RUN`.

The individual commands:

```sh
python -m phase_07_comparative_evaluation.evaluate_frozen --manifest STEP1/manifest.json \
  --model {phase_3a,phase_3b,phase_5_alpha_0,phase_5_alpha_1} --output RUN/MODEL \
  [--checkpoint-dir DIR] [--device cuda] [--batch-size 8] [--smoke] [--verify-only]
python -m shared.evaluate STEP1/phase6_test.shared.jsonl RUN/MODEL/predictions.jsonl --output RUN/MODEL/metrics.json
python -m phase_07_comparative_evaluation.statistical_analysis native --gold STEP1/phase6_test.shared.jsonl \
  --control RUN/phase_3a/predictions.jsonl --candidate RUN/phase_3b/predictions.jsonl \
  --control-label phase_3a --candidate-label phase_3b --output RUN/analysis/native_phase_3b_vs_phase_3a.json
python -m phase_07_comparative_evaluation.statistical_analysis native --gold STEP1/phase6_test.shared.jsonl \
  --control RUN/phase_5_alpha_0/predictions.jsonl --candidate RUN/phase_5_alpha_1/predictions.jsonl \
  --control-label phase_5_alpha_0 --candidate-label phase_5_alpha_1 --output RUN/analysis/native_phase_5_alpha_1_vs_alpha_0.json
python -m phase_07_comparative_evaluation.statistical_analysis native --gold STEP1/phase6_test.shared.jsonl \
  --control RUN/phase_3b/predictions.jsonl --candidate RUN/phase_5_alpha_0/predictions.jsonl \
  --control-label phase_3b --candidate-label phase_5_alpha_0 --output RUN/analysis/native_phase_5_alpha_0_vs_phase_3b.json
python -m phase_07_comparative_evaluation.statistical_analysis translated --output RUN/analysis/translated.json
python -m phase_07_comparative_evaluation.statistical_analysis errors --gold STEP1/phase6_test.shared.jsonl \
```

## Method

- **Decoding:** pinned Phase 3 settings: sequence length 384, stride 128, maximum answer length 64 tokens, and the top 20 start and end candidates.
  - Inference runs in eval mode under `torch.inference_mode()`, with dynamic padding.
  - The best valid passage span across all windows is kept.
  - Non-finite logits, incomplete windows or missing predictions stop the run.
  - Gold spans longer than 64 tokens stay in the denominator and are flagged for error analysis.
- **Scoring:** `shared.evaluate` (`agxqa-indic-v1`), with EM and token F1 on a 0–100 scale. Indic macro is the equal-weight mean of the four language scores.
- **Native intervals:**
  - Source documents are resampled with replacement within each language, keeping each document's questions together.
  - Both models get the same draws.
  - 10,000 draws, 95% percentile interval, seed 42.
  - The intervals describe document-sampling uncertainty for these fixed checkpoints.
- **Translated:**
  - The committed Phase 3 predictions are re-verified against their run manifests.
  - 3B − 3A intervals are recomputed by resampling source documents with `phase_03_multilingual_finetuning.scoring`.
  - The aligned English–Indic gap and the all-five-languages exact rate apply only to the translated data. Native questions are not parallel across languages.
- **Error analysis:**
  - For each Native language, the script samples 3B-recovered, 3B-newly-missed and both-wrong cases with a fixed seed.
  - It flags numerals, partial overlap (span boundaries), predictions longer or shorter than the gold span, the 64-token cap, and multi-window passages.
  - Valid alternative phrasing and unit errors need a human reviewer, using the private CSV.

## Rebuild the report from saved predictions

You don't need a GPU for this. With the private Step 1 files in `outputs/phase_07_comparative_evaluation/step1/`, and the run folder unpacked at `outputs/phase_07_comparative_evaluation/runs/native-20261125T202902Z/`, run these from the repository root. They are the commands used for the committed results.

```sh
RUN=outputs/phase_07_comparative_evaluation/runs/native-20261125T202902Z
GOLD=outputs/phase_07_comparative_evaluation/step1/phase6_test.shared.jsonl
for MODEL in phase_3a phase_3b phase_5_alpha_0 phase_5_alpha_1; do   # optional: rescore (needs fresh metrics paths)
  python -m shared.evaluate $GOLD $RUN/$MODEL/predictions.jsonl --output /tmp/$MODEL-metrics.json
done
# Rerun variation (computed after the server run; the server script now runs it automatically)
python -m phase_07_comparative_evaluation.statistical_analysis native --gold $GOLD \
  --control $RUN/phase_3b/predictions.jsonl --candidate $RUN/phase_5_alpha_0/predictions.jsonl \
  --control-label phase_3b --candidate-label phase_5_alpha_0 --output $RUN/analysis/native_phase_5_alpha_0_vs_phase_3b.json
python -m phase_07_comparative_evaluation.statistical_analysis report --run $RUN --output-dir phase_07_comparative_evaluation/results
python -m phase_07_comparative_evaluation.generate_plots --results phase_07_comparative_evaluation/results \
  --output-dir phase_07_comparative_evaluation/results/plots
```

The other analysis files come from the server run, using the commands listed under `commands` in `results/phase7_manifest.json`. That covers the 3B − 3A and α 1 − α 0 comparisons, the translated reuse and the error sample.

Before the report is written, it checks that:
- each model's metrics come from its verified predictions and gold file;
- each interval file was computed from exactly those predictions;
- every model used the same frozen dataset.

The report and analysis scripts never overwrite existing files, so delete the generated files first when rebuilding into the same folder.
